Tables don't scale

Every method so far stores one number per state, or per state–action pair. That is fine for Lesson 1's corridor of 6 cells. For real problems the table fails twice: it does not fit in memory, and the agent never visits most of its entries.

The maths

A tabular method stores $V(s)$ for every state, or $Q(s,a)$ for every pair. Memory grows as $|\mathcal{S}|$ or $|\mathcal{S}||\mathcal{A}|$, where $|\mathcal{S}|$ is the number of states and $|\mathcal{A}|$ the number of actions.

Raw sensor input makes $|\mathcal{S}|$ explode. An $n \times n$ image with $L$ grey levels per pixel has

$$L^{\,n^2} = 10^{\,n^2 \log_{10} L} \text{ possible values.}$$

Each pixel multiplies the count by $L$, so the exponent grows with the number of pixels. Most of those images never occur, but a table has no way to know which.

Data is the bigger problem. A Monte Carlo table entry is an average of $N(s)$ returns, so its standard error is

$$\operatorname{SE}\big[V(s)\big] = \frac{\sigma_s}{\sqrt{N(s)}}, \qquad N(s) \approx \mu(s)\,T,$$

where $\sigma_s$ is the standard deviation of the return from $s$, $T$ is the total number of steps of experience, and $\mu(s)$ is the fraction of time spent in $s$. If time is spread roughly evenly, $\mu(s) \approx 1/|\mathcal{S}|$, and

$$\operatorname{SE}\big[V(s)\big] \approx \sigma_s \sqrt{\frac{|\mathcal{S}|}{T}}.$$

To keep the same accuracy with 10 times more states, a table needs 10 times more experience. The reason is that each entry learns only from visits to its own state.

The way out is to replace the table with a function $\hat v(s, \mathbf{w}) \approx v_\pi(s)$ with a weight vector $\mathbf{w} \in \mathbb{R}^d$ and $d \ll |\mathcal{S}|$. Changing one weight then changes the estimate of many states, so experience in one state informs its neighbours. That is generalisation, and "Share within 10 groups" is its simplest form, state aggregation (S&B §9.3). Lessons 61 to 64 build it properly.
