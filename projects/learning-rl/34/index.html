Generalised policy iteration

Policy iteration evaluates fully, then improves. Value iteration evaluates for one sweep, then improves. Anything in between also works. Generalised policy iteration (GPI) is the name for any mix of the two processes, and nearly every method in this course is one.

The bridge from Lessons 32–33, slip $0.1$. Pick how many evaluation sweeps $m$ to run before each greedy improvement. Amber arrows are not yet optimal.

Each line is an average over the 21 cells where you choose an action. Green: the current estimate $v$. Blue: the true value $v_\pi$ of the current arrows. Amber dashed: $v_*$. Evaluation pulls green towards blue. Improvement lifts blue towards amber.

How much evaluation is worth it?

Each setting runs until the policy is stable and $\Delta < 10^{-4}$. An evaluation sweep computes one action value per cell. An improvement computes all four, so it costs as much as four sweeps. Cost = sweeps + 4 × improvements.

Neither extreme is cheapest. With $m = 1$ an expensive improvement follows every cheap sweep. With large $m$ most sweeps polish values for a policy that is about to change. A small $m$ between them, here 3, does least work. The more actions per state, the more an improvement costs, and the larger the best $m$.

The maths

GPI runs two processes on a value estimate $v$ and a policy $\pi$:

$$\begin{aligned} &\text{evaluation:} && v \to v_\pi \\ &\text{improvement:} && \pi \to \text{greedy}(v) \end{aligned}$$

Evaluation makes $v$ consistent with $\pi$. Improvement makes $\pi$ greedy with respect to $v$. Each one spoils the other: a new policy makes the old values wrong, and new values can make the policy no longer greedy.

The version here, called modified policy iteration, runs $m$ sweeps of Lesson 30's update and then one greedy improvement:

$$v(s) \leftarrow \sum_{s', r} p(s', r \mid s, \pi(s))\,\big[r + \gamma\, v(s')\big] \quad (m \text{ sweeps})$$ $$\pi(s) \leftarrow \arg\max_a \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma\, v(s')\big]$$

With $m = 1$ this is value iteration. As $m \to \infty$ it is policy iteration. By Lesson 30, $m$ sweeps multiply the worst evaluation error by at most $\gamma^m$, so large $m$ buys accuracy the next improvement may throw away.

Where it ends. Both processes stop changing things only when $v = v_\pi$ and $\pi$ is greedy with respect to $v$. Then

$$v(s) = \max_a \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma\, v(s')\big]$$

which is the Bellman optimality equation, so $v = v_*$ and $\pi$ is optimal. The processes compete in the short run and agree in the long run.

The sweeps need not even be complete or in order. Asynchronous DP (S&B §4.5) backs up states in any order, as long as every state keeps getting backed up. Monte Carlo (next unit) and TD learning are also GPI: they swap the model-based evaluation for estimates built from experience.
